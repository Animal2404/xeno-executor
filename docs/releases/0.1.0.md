**First public reference build.**

Xeno is an internal Luau runtime for Roblox on Windows x64: manual-map injection, a `lua_resume`-driven script scheduler, and a Dear ImGui workspace drawn over the game's D3D11 swapchain.

### Download

**[Download Xeno 0.1.0](https://www.mediafire.com/folder/7q4dz0de1v2y0/xeno+executor)**

The folder contains the release archive with `xeno.dll`, `xeno_injector.exe`, and `README.md`. **Extract the archive to a local folder before running anything** — start the injector from the extracted files, not from inside the archive. The archive is password-protected: `5139237619`. Binaries are unsigned, so Windows SmartScreen may ask for confirmation.

### Highlights

- **Manual-map injector** — maps `xeno.dll` without `LoadLibrary`, leaving no module-list entry.
- **`lua_resume` scheduler** — scripts are queued in the overlay and executed on a fresh Luau thread on the next resume.
- **In-game workspace** — Editor, Console, Settings, and About tabs rendered over `IDXGISwapChain::Present`; toggle with `INSERT`.
- **Script API** — `getgenv`, `getrenv`, `identifyexecutor`, `checkcaller`, closure helpers, `loadstring`, `hookmetamethod`, `getrawmetatable`, `getnamecallmethod`, `setclipboard`, `queue_on_teleport`, and synchronous HTTP via `request` / `syn.request`.
- **Runtime signatures** — override the `lua_resume` pattern through `%LOCALAPPDATA%\Xeno\signatures.ini`, no rebuild required.
- **Autoexec** — `.lua` files in `%LOCALAPPDATA%\Xeno\autoexec` are queued when Xeno attaches.

### Quick start

1. Download the archive from the download folder above.
2. Extract it to a local folder (right-click the archive, then **Extract All**) and enter the archive password: `5139237619`.
3. Launch Roblox and join a game.
4. Start the injector from the extracted folder as administrator:

   ```powershell
   .\xeno_injector.exe .\xeno.dll
   ```

5. Press `INSERT`, paste a script, and press **Execute**.

### Requirements

- Windows 10 or 11, x64.
- Administrator rights for the injector.
- A D3D11 game window; borderless or windowed mode is recommended for the overlay.

### Known limitations

- The default `lua_resume` signature is a starting point. Calibrate it for the client build you attach to; see `docs/UPDATING.md`.
- Scripts run synchronously. `task.wait`, `wait`, and other yields are reported as execution errors.
- `request` is synchronous WinHTTP and blocks the game thread until the transfer completes.
- The manual mapper does not run TLS callbacks, process delay-load imports, or register x64 exception tables. Import bases assume per-boot system module addresses.
- No anti-cheat bypass is included; injection may fail on protected clients.

### Build from source

```powershell
cmake --preset msvc-x64
cmake --build --preset release
```

Requires Visual Studio 2022 (Desktop development with C++) and CMake 3.24 or newer. See `README.md` for details.
